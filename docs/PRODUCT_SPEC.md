# 공간 — 실제 서비스 구현 제품 명세

작성 기준: 2026-10-24. 소유자: 김민영. 제품명: **공간 / GONGGAN**.
브랜드 문구: **상상을, 실제 공간으로. / FROM IMAGINATION TO REAL SPACE.**
저장소명은 소유자가 지정한 `ai-interior-gongan`을 그대로 사용한다.

이 문서에서 **확정 요구**는 기존 대화에서 정한 제품 목표다. **설계 제안**은 이를
실제로 구현하기 위한 인수 설계이며, 이미 구현되었거나 소유자가 기술 스택을 승인했다는 뜻이 아니다.
**후속 확장**은 제품 방향을 기록한 것으로 1차 출시를 지연시키는 필수 조건이 아니다.

## 1. 어떤 서비스를 만들고 있는가

인테리어를 원하는 일반 고객과 인테리어 업체가 하나의 작업 공간에서
도면 확보 → 공간 구조 확인 → 인테리어 시안 비교 → 실제 구매 가능한 자재 탐색 →
결과 저장/전달 → 업체의 설계 작업으로 이어지도록 하는 플랫폼이다.

핵심 가치는 다음 세 가지다.

1. 전체 집의 구조를 이해하고 같은 콘셉트를 유지하는 실사 시안 **5개 이상** 제공. 기본 목표 6개.
2. 시안에 보이는 바닥·벽·필름·가구 등에 대해 **실제 브랜드·제품명·품번·AI Visual Match Score** 제공.
3. **도면으로부터 복원한 구조와 선택한 시안의 자재 정보를 편집 가능한 SketchUp 모델로 연결**.

이미지 생성만 하고 끝나는 서비스가 아니다. 그러나 생성 이미지가 곧 정확한 시공 도면이거나
그 사진 안의 모든 형태를 원형 그대로 3D 복원할 수 있다는 의미도 아니다.
정확한 기하 구조는 검증된 도면 데이터를 기준으로 삼고, 이미지의 스타일·재료 정보를 결합한다.

## 2. 대상과 권한

| 구분 | 주요 작업 | 기본 진입 및 범위 |
|---|---|---|
| B2C 일반 고객 | 우리 집 스타일 탐색, 예산 비교, 자재 저장 | 우리 집 찾기를 앞에 배치하고 직접 업로드도 항상 제공 |
| B2B 인테리어 업체 | 고객별 여러 현장, 제안서, 자재 목록, 후속 설계 | 직접 업로드 중심, 주소 검색도 제공 |
| B2B Pro | 업체 기능 + SketchUp 변환 | 실제 서버 권한·구독 확인 후 사용 |
| 조직 구성원 (제안) | 프로젝트 협업 | owner/admin/editor/viewer 역할별 접근 |
| 플랫폼 운영자 (제안) | 도면·제품 DB 검수, 작업·비용·지원 관리 | 일반 업체 콘솔과 분리한 운영 권한 |

확정된 수익 방향은 Basic/Pro 구독이며 B2B Pro에 SketchUp을 포함한다.
월 가격, 무료 크레딧, 생성 횟수, 인원 수, 저장 용량, 초과 과금은 미정이다.
임의 가격을 운영 결제에 넣지 않는다. 출시 전 가격표와 사용량 차감 정책을 결정한다.

## 3. UX와 기존 디자인 보존

- 밝은 화이트/라이트 그레이, 보라색 액센트, 차분하고 전문적인 인테리어 SaaS.
- 데스크탑 우선. 1440/1920px에서 갤러리·비교·콘솔을 읽기 편하게 구성.
- 기존 랜딩, 사이드바, 카드, 글꼴, 버튼, 문구와 주요 구성을 최대한 유지.
- 랜딩의 좌우 여백 없이 화면을 채우되 글자·사진·버튼·세로 높이까지 비례 확대한다.
- 모바일에서도 업로드·열람·저장은 가능해야 하나 전체 설계 편집은 데스크탑 우선.
- 작업 중, 부분 성공, 재시도 가능 실패, 설정 미완료, 권한 부족, 결과 없음 상태를 별도로 보여준다.
- 로딩 애니메이션을 실제 진행률처럼 가장하지 않는다. 단계 진행과 실제 완료 개수를 구분한다.

## 4. 입력과 프로젝트 생성

### 4.1 두 가지 진입

**우리 집 찾기**: 주소/단지명 → 단지 선택 → 전용·공급면적 및 타입 선택 →
평면도 미리보기 → 확장 여부/좌우 반전/구조 변경 확인 → 사용자가 구조 확정 → 공간 조건 입력.

**직접 업로드**: PDF/평면도 이미지/SketchUp 스크린샷 → 입력 종류 확인 → 공간 조건 → 분석.

도면이 없거나 사용자의 집과 다르면 업로드로 자연스럽게 넘어간다.
검색 결과가 없다는 이유로 유사한 다른 단지의 도면을 정답처럼 자동 선택하면 안 된다.
동·호수는 필요한 경우만 최소 수집하고 타 사용자에게 노출하지 않는다.

### 4.2 프로젝트 입력 필드

| 필드 | 요구 |
|---|---|
| 이름 | 필수, 사용자 수정 가능 |
| 계정/조직 | 로그인 세션과 멤버십에서 서버가 결정 |
| 원본 유형 | `floorplan_pdf`, `floorplan_image`, `sketchup_screenshot`, `catalog_floorplan` |
| 파일 | 현재 PDF/JPG/PNG/WebP, 20MB 기준을 유지. 확대는 별도 검토 |
| PDF 페이지 | 다중 페이지 미리보기, 분석할 페이지 명시 선택 |
| 공간 유형 | 주거/업무/상업. 1차 실제 분석 품질은 아파트부터 검증 |
| 콘셉트 | 기존 6종 + 원하는 느낌 자유 텍스트 |
| 예산 | UI 만원, 저장 원(KRW), 자재비만인지 전체 공사비인지 범위 확인 |
| 층고 | mm, 비어 있으면 2400. 기본값이라는 출처 표시 |
| 면적/기준 길이 | 인식 실패 시 입력. 확인하지 않은 수치를 확정값으로 쓰지 않음 |
| 유지/변경 조건 (제안) | 구조·창호·문 위치 유지, 가구 유지 등 |
| 참고 이미지 (후속) | 권한 있는 스타일 참고, 원본 도면과 별도 저장 |

`.skp` 원본 파일 업로드·모델 전체 해석은 현재 요구의 스크린샷 입력과 다른 기능이다.
이번 1차 구현에 자동 포함하지 말고 별도 확장으로 관리한다.

## 5. 주소와 평면도 DB

주소 검색 API는 주소 정규화/좌표 검색을 위한 도구이고 평면도 DB는 별도 자산이다.
네이버 지도 API 키 하나로 네이버 부동산의 모든 평면도를 가져올 수 있다고 가정하지 않는다.

**공간의 구현 방향**:

- 주소 공급자와 도면 공급자를 별도 인터페이스로 분리.
- 권한을 확보한 건설사/제휴사/자체 제작/검수된 제출 도면을 자체 DB에 쌓는다.
- 단지, 도로명·지번, 건물 식별자, 전용/공급 면적, 타입, 확장/반전 버전, 원본 출처를 기록.
- 도면 파일마다 저장·표시·AI 분석·파생 3D 제작 범위의 이용 권한과 만료 여부를 관리.
- 사용자 업로드는 기본 비공개. 공용 도면 DB 편입은 별도 동의와 검수 후 수행.
- 제휴 API가 확보되면 공급자 어댑터 추가. 계약 범위 밖의 재배포나 AI 사용은 차단.
- 처음부터 전국 커버리지를 약속하지 않는다. 확보된 단지 수와 검색 성공 범위를 사실대로 표시.
- 운영자는 도면 버전·중복·타입 연결을 검수하고 잘못된 도면을 비활성화할 수 있어야 한다.

경쟁사 내부 수집 방식을 그대로 복제한다는 전제로 구현하지 않는다. 과거 대화의
경쟁사 사례는 시장 참고이며 이 프로젝트의 사용 허가나 공급 계약을 의미하지 않는다.

## 6. 공간 분석

도면 입력은 PDF/이미지 전처리 → OCR/도형 인식 → 구조 모델 → 치수 검증 → 사용자 수정으로 진행한다.
각 방의 폴리곤, 벽, 벽 두께, 문·창 위치와 크기, 기준 길이, 층고, 원본 좌표계를 보관한다.
필드마다 `source`(OCR/도형/사용자/기본값)와 confidence, 검수 상태를 갖는다.

- 전용면적·공급면적·분석한 바닥면적을 혼용하지 않는다.
- ㎡ → 평은 `m² / 3.305785`로 표시하고 반올림은 표시 시에만 적용.
- 치수 OCR 값, 스케일 적용값, 사용자가 확정한 실측값을 분리한다.
- 기준 길이나 스케일이 없으면 정확한 치수를 추정 확정하지 않고 보완 요청.
- 방향/왜곡/저해상도/겹친 치수선 등으로 분석 신뢰도가 낮으면 재업로드 또는 수동 수정 제공.
- 구조 수정은 분석 버전을 새로 만들며 이미 생성한 시안은 어느 구조 버전에 연결됐는지 유지.

**스크린샷 입력**은 보이는 공간의 구도·재질 변경에 집중한다.
화면 밖 방·실측 면적은 미상으로 표시하고, 전체 집 구조 일관성 보장은 도면 기반과 구분한다.
스크린샷은 이미지 스타일 탐색에는 유효하지만 단독 SKP 변환 경로는 제공하지 않는다.

## 7. AI 시안 생성

기본 6개 스타일: 모던 미니멀, 내추럴 우드, 스칸디 내추럴, 소프트 럭셔리,
모던 인더스트리얼, 웜 클래식. 필요하면 사용자 컨셉을 반영하되 최소 5개 실제 시안을 목표로 한다.

도면 기반에서는 한 집의 구조 모델, 카메라, 컬러·자재 팔레트와 디자인 규칙을 공유한다.
거실·주방·침실·욕실 결과가 같은 집의 같은 콘셉트라는 인상을 유지해야 한다.
구조 보존은 텍스트 프롬프트만으로 보장하지 않는다. 검증된 기하에서 얻은 깊이/경계/영역 마스크 등
지원되는 제어 입력을 사용하거나, 먼저 3D 구조 미리보기를 만들고 시각화하는 접근을 검증한다.

**설계 제안**: 먼저 6개 스타일의 대표 공간을 생성하고 선택된 스타일의 나머지 방을 생성하여 비용을 관리한다.
집 전체 일관성이라는 최종 요구는 유지한다. 방별 생성 범위와 소요 크레딧을 실행 전 알린다.

생성 작업에는 입력·구조 버전·모델/공급자·설정·시드(지원 시)·비용·지연·실패 이유·결과 파일을 연결한다.
6개 중 일부 실패하면 성공분을 보존하고 실패분만 재시도. 5개 미만이면 완료가 아니라 부분 성공으로 표시한다.
재생성으로 기존 결과를 덮어쓰지 않는다. 선택한 시안만 새 버전으로 저장한다.
실제 공급자 미설정 시 `provider_not_configured`로 안내하며 샘플 사진을 실제 결과로 반환하지 않는다.

## 8. 실제 자재 DB와 매칭

**1차 필수**: 마루·벽지·필름·가구. 현재 데모에 조명이 있으나 확대 카테고리로 관리 가능.
**후속**: 조명·타일·도어·싱크대 및 제품 DB를 제약 조건으로 먼저 적용한 생성 모드.
브랜드 확장 후보는 동화마루·LX하우시스 등이며 계약/데이터 확보 상태는 미확정이다.

제품 레코드는 브랜드, 제품/컬렉션 이름, 품번, 색상/패턴, 카테고리, 규격,
실제 제품 이미지/텍스처, 출처 URL, 자료 기준일, 활성/단종 상태, 이용 권한을 가져야 한다.
가격이 있다면 통화·단위·세금/배송/시공 포함 여부·기준일을 함께 저장한다.
품번 없이 LLM이 지어낸 제품을 추천 DB에 넣지 않는다.

PDF 카탈로그 수집 → OCR/표 추출 → 제품/이미지 분리 → 정규화 → 중복 검출 →
운영자 검수 → 임베딩/검색 색인 → 게시 순서로 운영한다.
수집 담당 파트너가 구축한 데이터는 실제 파일/스키마를 받아 확인한 뒤 연결한다.
이 인수본에 해당 파트너 DB가 포함되어 있다고 가정하지 않는다.

**AI Visual Match Score**:

- 결과 이미지의 바닥/벽/필름/가구 영역을 분리하여 동일 카테고리의 실제 제품과 비교.
- 임베딩 유사도에 색상·패턴·질감 등 검증 가능한 특성을 결합하고 별도 검증 데이터로 보정.
- 카메라·조명·그림자 때문에 사진 색상과 실물은 다를 수 있음을 제품 상세에서 설명.
- 0~100 점수는 시각적 유사도 지표. 95점이 95% 확률로 같은 제품이라는 뜻이 아니다.
- 생성에 정확한 SKU가 사용된 경우와 생성 후 비슷한 제품을 찾은 경우를 구분한다.
- 카테고리별 후보 Top-K, 근거, 평가 모델 버전과 점수 산출 시점을 저장.
- 유효 후보가 없으면 추천 없음/낮은 신뢰도로 반환. 억지로 높은 점수를 만들지 않는다.

과거 목표인 90~95%는 제품 방향이지 달성한 성능 수치가 아니다.
전문가가 판단한 Top-K 적합도, 순위 품질, 카테고리별 오추천률 등의 기준을 먼저 정의한다.

## 9. 예산과 견적

예산은 스타일 선택 제약이자 사용자의 기대 범위다. 실제 견적서가 아니다.
제품 가격이 확보된 항목만 수량/면적·단위·손실률을 반영해 계산하고,
철거·인건비·설비·전기·운반 등 누락 공종을 분리한다. 미확보 가격은 0원이 아닌 미확인으로 표시한다.
시공업체 확정 견적과 AI 추정 예산을 구별한다. 신뢰할 데이터가 없으면 입력 예산만 보여준다.
데모의 단순 예산×계수를 실제 비용 추정 로직으로 사용하지 않는다.

## 10. SketchUp

이 기능은 B2B의 핵심 차별점이며 가짜 파일/미리보기만으로 완료 처리하지 않는다.

허용 조건: B2B Pro 활성 권한, 프로젝트 편집 권한, 도면 원본, 스케일·구조 검수 완료,
파생 모델 제작이 허용된 원본. 서버가 조건을 모두 확인한다.

처리: 확정 구조 모델 → 벽/바닥/천장/문/창 기하 생성 → 선택한 콘셉트의 재질 배치 →
그룹/컴포넌트/태그 정리 → SketchUp 파일 출력 → 실제 SketchUp에서 열기·편집 검증.
벽체·문·창·바닥을 구분하고 재료에 연결된 실제 SKU 메타데이터를 유지한다.
가구는 허가된 모델이 있을 때 사용하며, 없으면 치수가 확인된 단순 프록시임을 명시한다.

구현 경로는 공식 C SDK 기반 별도 변환 워커 또는 SketchUp 내 Ruby 확장 프로그램을 평가한다.
서버 `.skp` 다운로드와 사용자가 확장 프로그램을 설치하는 방식은 UX가 다르므로 혼동하지 않는다.
사용 OS·SDK 제공 조건·라이선스·출력 버전은 기술 검증 후 확정한다.
사용자의 SketchUp 2025 사용 이력을 기준으로 우선 호환 확인하되 이전 버전 지원은 별도 테스트한다.
GLB/OBJ/JSON 출력만으로 `.skp` 완료를 선언하지 않는다.

## 11. 저장·다운로드·협업

- 로그인 후 다른 기기에서도 프로젝트·시안·자재 선택·원본을 복원.
- 프로젝트 JSON과 자재 CSV를 유지하고 실제 이미지 다운로드 제공.
- 제안 PDF/ZIP은 제안 범위. 브랜드, 제품, 점수 의미, 출처, 프로젝트/분석 버전 포함.
- 원본 파일 다운로드와 삭제에 소유권 검사. 미리보기/다운로드 URL은 권한 확인 및 만료 적용.
- 업체 콘솔: 고객명, 상태(시안 검토/고객 검토/시안 확정/완료), 내부 메모, 검색·목록 출력 유지.
- 팀 초대/권한과 고객 검토 링크는 제안 기능. 내부 메모는 고객 링크에서 제외.
- 고객 공유는 사용자가 명시적으로 생성·취소 가능하며 기본 비공개.
- 브라우저별 기존 데모 데이터를 조직의 실제 데이터로 자동 공유하지 않는다.

## 12. 가입·구독·운영

실제 이메일/OAuth 로그인, 세션 만료·로그아웃·계정 복구, B2B/B2C 프로필을 구현한다.
업체라는 표시와 인증된 업체 여부는 구분한다. 사업자 검증 절차는 별도 정책 결정 사항이다.
구독 연동은 테스트 모드부터 구현하고 서명 검증된 결제 웹훅으로 권한을 갱신한다.
브라우저의 성공 페이지나 사용자가 수정 가능한 필드로 Pro를 부여하지 않는다.
중복 웹훅·중복 생성 요청은 비용이나 크레딧이 두 번 차감되지 않아야 한다.
운영자는 오류 작업, 사용량, 수집 DB 품질, 삭제 요청, 권한 문제를 확인할 수 있어야 한다.

## 13. 후속 확장

공정 스케줄 자동 생성, 시공업체 연결, 현장관리자 파견, 계약서 템플릿/보관,
직접 결제 또는 플랫폼 결제, 해외 B2B 확장, 실제 제품만 사용하는 제약 기반 생성.
이 항목은 기존 사업 구상을 보존하기 위한 목록이다. 별도 정책·운영·데이터·결제 설계 없이
1차 MVP에 구현 완료라고 표시하지 않는다.

## 14. 미확정 사항과 안전한 기본값

| 미확정 항목 | 개발 중 기본 원칙 |
|---|---|
| AI 공급자·모델·비용 | 교체 가능한 어댑터, 실제 데이터로 품질·비용 비교 후 선정 |
| 주소 공급자·도면 계약 | 주소 검색과 자체 도면 DB 분리, 확보 범위부터 제공 |
| 파트너 자재 DB | 샘플 파일과 스키마를 받아 검수, 미제공 데이터를 있다고 가정하지 않음 |
| 구독 가격·차감 정책 | 설정 가능한 요금표, 운영 과금 전 소유자 결정 |
| SKP 출력 엔진·운영체제 | 기술 검증을 초기에 수행, 나머지 개발과 독립시킴 |
| 배포 호스팅/리전 | 현 운영 사이트 유지, 스테이징에서 먼저 검증 |
| 보관·삭제 기간 | 설정으로 분리, 서비스 정책 확정 후 운영 반영 |

## 15. 완료 정의

실제 입력을 업로드한 사용자가 인증된 자기 프로젝트에서 분석을 확인·수정하고,
실제 생성된 5개 이상의 시안과 DB에 존재하는 제품 매칭을 확인하며, 새 기기에서도
복원하고 다운로드할 수 있어야 한다. 권한을 갖춘 B2B Pro의 검증된 도면은 실제
SketchUp에서 열리고 편집되는 파일까지 만들어져야 한다.
모델 품질·API 비용·도면 공급 범위·라이선스·운영 한계는 측정/검증된 범위대로 명시한다.
미연결 공급자, 모의 응답, 임시 파일만 있는 기능은 이 완료 정의를 충족하지 않는다.
