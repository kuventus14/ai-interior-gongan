# Claude Code에 전달할 시작 요청문

아래 내용을 저장소 루트에서 Claude Code에 전달한다.

```text
이 저장소는 내가 만드는 인테리어 AI 플랫폼 '공간'의 현재 웹 데모다.
나는 기존 UI를 유지하면서 모든 핵심 흐름을 실제 서비스로 개발하려고 한다.

먼저 CLAUDE.md, docs/CURRENT_STATE.md, docs/PRODUCT_SPEC.md,
docs/IMPLEMENTATION_PLAN.md를 읽고 현재 코드와 문서가 일치하는지 확인해줘.
README의 명령으로 데모를 실행하고 현재 UX를 기준으로 삼아줘.

제품 목표는 다음과 같다.
1. B2B/B2C 실제 로그인과 계정/조직별 프로젝트 저장.
2. 주소/아파트명으로 자체 또는 정식 제휴 도면 DB 검색.
   타입·면적·확장·반전을 사용자가 확인하고, 없거나 다르면 직접 업로드.
3. PDF/평면도 이미지/SketchUp 스크린샷 + 콘셉트/예산/층고 입력.
   기본 층고는 2400mm. 스크린샷만으로 실측 구조를 꾸며내지 않기.
4. 실제 도면 분석, 신뢰도/치수 확인, 사용자 구조 수정.
5. 집 전체 콘셉트를 유지하는 실제 실사 시안 최소 5개, 기본 6개.
6. 실제 제품 DB 기반 브랜드·제품명·품번과 AI Visual Match Score.
   점수는 시각적 유사도이며 제품 동일성 확률로 표현하지 않기.
7. 저장·비교·자재 선택·이미지/JSON/CSV 다운로드, 기기 간 복원.
8. 업체 콘솔과 팀 권한, 내부 메모, 고객 검토 흐름.
9. B2B Pro의 검증된 도면만 실제 SketchUp 파일로 변환.
   확정 기하 + 선택 시안의 재질을 연결하고 실제 SketchUp에서 열어 검증.
10. Basic/Pro 구독, 사용량·작업 비용·실패 재시도·운영 관리.

현재 사진/분석/점수/로그인/SKP는 데모라는 사실을 잊지 마.
실제 공급자를 붙이고 검증하기 전에는 데모 표시를 없애거나 가짜 성공을 반환하지 마.
기존 랜딩의 비례 확대, 밝은 보라색 UI, 다른 화면의 디자인은 임의로 바꾸지 마.
네이버 주소 API와 평면도 공급은 다른 문제다. 권한 없는 수집을 전제로 구현하지 마.
API 키는 서버에만 두고 인증/Pro/프로젝트 권한은 서버에서 검증해줘.

설명이나 계획만 작성하고 끝내지 말고 다음 순서로 실제 개발을 시작해줘.
- 현재 코드 실행과 한계 확인.
- 기술 스택/데이터 구조/이전 방식을 결정하고 이유 기록.
- 실제 도면 구조 추출과 SKP 파일 생성의 기술 검증을 초기에 수행.
- 인증·DB·파일 저장·프로젝트 CRUD를 첫 실행 가능한 단계로 구현.
- 이후 주소 검색, 분석, 생성, 자재, SKP, 협업/결제를 단계적으로 연결.
- 각 단계의 수용 테스트를 실행하고 작은 커밋으로 남기기.

API 키/계약/결제 정책처럼 내가 제공해야 하는 것은 한 번에 정리해줘.
그것이 없어도 할 수 있는 코드·인터페이스·오류 처리·테스트는 계속 진행해줘.
운영 과금, 유료 자원 생성, 기존 공개 사이트 교체는 별도 결정이 필요하다.
현재 GitHub push가 기존 Sites 자동 배포라고 가정하지 마.
완료/데모/외부 입력 대기를 구분해 docs/PROGRESS.md에 기록하고,
다음 세션이 바로 이어갈 수 있게 실행 명령·테스트 결과·남은 작업을 남겨줘.
```
